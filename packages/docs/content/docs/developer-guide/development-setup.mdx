## Prerequisites

- **Node.js** 24.x
- **pnpm** 10.x+ (required — npm and yarn are not supported)
- **PostgreSQL** 15+ (or use Docker)
- **Docker** (for running the full stack locally)

## Clone and Install

```bash
git clone https://github.com/elmohq/elmo.git
cd elmo
pnpm install
```

## Configure Environment

Create a `.env` file at the repo root. This config runs local mode with no API keys: the `stub` provider returns placeholder answers and judgements, which is enough for UI work.

```bash
DATABASE_URL=postgres://postgres:postgres@localhost:5432/elmo
DEPLOYMENT_MODE=local
BETTER_AUTH_SECRET=any-random-string
# Generate with: openssl rand -base64 32
ELMO_ENCRYPTION_KEY=
APP_URL=http://localhost:3000
VITE_APP_URL=http://localhost:3000
DISABLE_TELEMETRY=1
SCRAPE_TARGETS=stub:stub
ONBOARDING_LLM_TARGET=stub:stub
TYPESAFE_API_KEY=stub
```

Then copy it into the web app, since Vite reads `.env` from `apps/web` and the worker loads that copy too:

```bash
cp .env apps/web/.env
```

To track real answer engines, replace the stub values: point `SCRAPE_TARGETS` at the engines you want and add each provider's keys, add one direct LLM key (`OPENAI_API_KEY`, `OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, or `MISTRAL_API_KEY`) for onboarding and the Opportunities report, and set `TYPESAFE_API_KEY` for the [mention judge](#mention-judge). [Configuration](/docs/developer-guide/configuration#environment-variables) lists every variable.

## Database Setup

Run Drizzle migrations to create the schema:

```bash
pnpm --filter @workspace/lib exec drizzle-kit migrate
```

## Mention Judge

The worker judges mentions and sentiment with [Jev](/docs/developer-guide/configuration#mention-judging), so it needs `TYPESAFE_API_KEY`, or `OPENROUTER_API_KEY` to call Jev through OpenRouter. For UI work without a key, set it to `stub`: answers get placeholder judgements and nothing is sent anywhere.

## Start Development Servers

Run all development servers in parallel:

```bash
pnpm dev
```

This starts:
- **Web app** at `http://localhost:3000`
- **Worker** process for background jobs

Or run only the web app:

```bash
pnpm --filter @workspace/web dev
```

## Development with Docker

For a setup closer to production, use the CLI in dev mode:

```bash
# Build from local source instead of pulling images
elmo init --dev

# Rebuild after code changes
elmo compose build
elmo compose up -d
```

The Docker build uses a multi-stage `docker/Dockerfile` with separate targets for `web` and `worker`.

## Component Stories

Elmo uses Storybook for component development in isolation:

```bash
pnpm --filter @workspace/web storybook
```

Stories live in `apps/web/src/stories/` and cover the app sidebar, prompt charts, and other components across deployment modes.
