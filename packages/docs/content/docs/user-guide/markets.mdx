---
title: Markets
description: Track a prompt in the countries and languages your customers use, and compare markets side by side.
---

AI answers depend on where a question is asked from and what language it's asked in. The same question gets different sources, shops, and competitors in the UK than in the US, and Google only shows an AI Overview for some queries in some places. In Elmo, a prompt is tracked in one or more **markets**: a country and a language together, such as `GB · EN` or `CH · FR`.

## Tracking a prompt in several markets

On the **Prompts** settings page, each prompt shows its markets as chips under its text. New prompts start in the market most of your prompts already use (the United States in English, for a new brand).

- **+ Market** adds a market. It starts from the text you're looking at, so translate it for that market before saving.
- Click a chip to see and edit that market's wording, and to switch it on or off. Tags apply to the prompt in every market.
- **Add Multiple** takes several markets at once and adds every pasted line in each of them.

Once saved, a market can't be changed. That would mix two markets into one history. Switch it off and add the one you want instead. Each market counts toward your prompt limit, since each one is run separately.

For anything more local than a country, put the place in the prompt itself (for example `best running shop in Manchester`).

## Filtering

Once a brand's prompts span more than one country or language, a **Markets** filter appears next to the tag filter on every dashboard page, with a section for countries and one for languages. Pick one to see that market on its own, or several to see them combined. With nothing picked, every market is included. In the prompt list, each prompt shows its market and how many markets it's tracked in, and a prompt's page has a **Markets** switcher to move between them.

The API and MCP server take the same filters as `countries` and `languages` parameters, both comma-separated (`countries=GB,IE`, `languages=en`). Prompts tracking the same question in different markets share a `groupId`; pass one when creating a prompt to add a market to an existing question, or to `GET /prompts` and `list_prompts` to list a question's markets.

## Which platforms can answer from a country

Each provider localizes in its own way, and not every one can. For a prompt outside the US, Elmo only runs it on the platforms that can actually answer from that country, rather than storing a US answer under another country's name. A prompt's page has a **How each model runs this prompt** section listing, for each model, whether it runs from the prompt's country and whether its language is sent.

| Provider | Country | Language |
| --- | --- | --- |
| Cloro | All platforms | From the prompt's wording |
| Oxylabs | All platforms | From the prompt's wording |
| Olostep | All platforms, from the US, UK, Germany, France, and Singapore only | From the prompt's wording |
| DataForSEO | All scraped surfaces. The ChatGPT and Gemini scrapers don't cover Hong Kong or Taiwan. Not targets pinned to a model version (LLM Responses) | Sent on the scraped surfaces |
| BrightData | ChatGPT and Google AI Overview | Sent for Google AI Overview |
| SearchApi | Google AI Mode and Google AI Overview | Sent for the Google surfaces |
| OpenAI API, Anthropic API | Targets with web search on (`:online`) | From the prompt's wording |
| Mistral API, OpenRouter | None with web search on | From the prompt's wording |

A model called **without** web search answers the same everywhere, so it runs every prompt in every country. Each run records the country and language it actually sent, which the API returns as `country` and `language` on every run. Each is `null` when the platform didn't take it.

Coverage within a provider also varies by platform. For example, Google AI Mode isn't offered in every country, and Cloro's supported countries differ by platform. A run the provider can't serve fails without storing a result.
